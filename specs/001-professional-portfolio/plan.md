# Implementation Plan: Portfolio profesional personal

**Branch**: `001-professional-portfolio` | **Date**: 2026-11-24 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-professional-portfolio/spec.md` and the user-provided stack and project structure.

## Summary

Create a public, single-page professional portfolio for Joaquín Felipe Díaz. It presents verified profile information, projects, technologies, skills, education, credentials, CV, contact links, and the GLUTN Android download when available. The implementation uses React 19 and strict TypeScript with Vite, Tailwind CSS, Motion for React, and Lucide React. All editable portfolio content lives in typed TypeScript data modules. The app has no backend or database. Delivery uses GitHub-connected Vercel production and preview deployments.

## Technical Context

**Language/Version**: TypeScript with `strict: true`; React 19. Use mutually compatible stable package releases at implementation time and commit the npm lockfile.

**Primary Dependencies**: React 19, Vite with the official React plugin, Tailwind CSS 4 with `@tailwindcss/vite`, Motion for React (`motion`, imported from `motion/react`), and `lucide-react` with named imports for used icons only. Development tooling: ESLint with the TypeScript ESLint flat configuration, Prettier, Vitest, React Testing Library, `@testing-library/user-event`, `@testing-library/dom`, and `jsdom`.

**Storage**: No server storage, backend, or database. Portfolio data is version-controlled TypeScript; stable downloadable files are stored under `public/documents/`.

**Testing**: Vitest in a DOM environment, React Testing Library with role/name-based queries, and `user-event` for realistic keyboard and pointer interaction. Include type checking in the production build. Scripts: `dev`, `build`, `test`, and `lint`.

**Target Platform**: Modern browsers on mobile, tablet, and desktop; minimum layout width 320 px. Static production hosting on Vercel, connected to GitHub. Target Node.js 22.12 or newer for local and CI tooling compatibility; confirm the selected stable Vite/Vitest versions during implementation.

**Project Type**: Static single-page web application; frontend only.

**Performance Goals**: Lighthouse Performance, Accessibility, Best Practices, and SEO each above 90 on both mobile and desktop production measurements. Avoid horizontal overflow, layout shifts, unnecessary client JavaScript, unneeded dependencies, and non-priority eager media loading.

**Constraints**: No backend, database, authentication, or admin panel. Do not publish unverified personal claims or nonfunctional links. CV/APK/certificate actions appear only for available files. Respect WCAG 2.2 AA and reduced-motion preferences. Preserve direct stable paths for public documents. Do not add packages without a documented need.

**Scale/Scope**: One public portfolio page with nine content sections (Hero, About, Projects, Technologies, Skills, Education, Certificates, Resume, Contact), shared header/footer, three initial project records, a small personal content collection, and filterable credentials. No user accounts, dynamic server state, or multi-tenant scale requirements.
